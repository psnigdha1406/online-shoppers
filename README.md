# online-shoppers
# Online Shoppers Intention — Project 3

**Date:** 20-Jan-2023

## Problem Statement

The dataset comes from an online retailing company. The goal is to analyze visitors' on-site browsing activity to predict **which online shoppers are likely to generate revenue** (i.e., complete a purchase) based on their session behavior.

## Data Dictionary

| Column | Description |
|---|---|
| `Administrative` | Number of "Administrative" pages visited (e.g. account settings) |
| `Administrative_Duration` | Time spent on Administrative pages |
| `Informational` | Number of "Informational" pages visited |
| `Informational_Duration` | Time spent on Informational pages |
| `ProductRelated` | Number of product-related pages visited |
| `ProductRelated_Duration` | Time spent on product-related pages (in minutes) |
| `BounceRates` | % of visitors who land on the page and leave without any further interaction |
| `ExitRates` | % of visitors for whom this was the last page viewed in the session |
| `PageValues` | Average value of a page, calculated as revenue generated by the page ÷ number of views — used to identify high- and low-performing pages |
| `SpecialDay` | Closeness of the visit date to a special day (Mother's Day, Valentine's Day, etc.), expressed as a probability |
| `Month` | Month in which the session occurred |
| `OperatingSystems` | Operating system used by the visitor (coded) |
| `Browser` | Browser used by the visitor (coded) |
| `Region` | Visitor's region, coded as a number |
| `TrafficType` | Source of the traffic — referral, direct, organic (search), social, or paid — coded as a number |
| `VisitorType` | First-time visitor vs. Returning visitor |
| `Weekend` | Whether the visit occurred on a weekend (Boolean) |
| `Revenue` | **Target variable** — whether the session ended in a purchase (Boolean) |

### Notes on key metrics
- **Bounce Rate**: high values suggest visitors aren't finding what they need on that page.
- **Exit Rate**: high values on a specific page may point to content, design, or usability issues on that page.
- **Page Value**: useful for spotting which pages drive revenue and which underperform, but should be read alongside other metrics since it only reflects an average, not conversion counts or customer lifetime value.
- **Traffic Type** breakdown (referral, direct, organic, social, paid) helps determine which marketing channels bring the most valuable customers, informing budget allocation.
- **Visitor Type**: "First-time" = new within the date range; "Returning" = has visited before and come back within the date range.

## Suggested Project Workflow

Based on the dataset and target variable, this looks like a binary classification task. A typical approach:

1. **Exploratory Data Analysis (EDA)** — distributions of numeric features, class balance of `Revenue`, correlations, and behavior differences between purchasers and non-purchasers.
2. **Data Cleaning & Preprocessing** — handle missing values/outliers, encode categorical fields (`Month`, `VisitorType`, `TrafficType`, etc.), and scale numeric features as needed.
3. **Feature Engineering** — e.g., combine duration/page-count features, derive session engagement scores.
4. **Modeling** — train classification models (e.g., Logistic Regression, Decision Tree, Random Forest, XGBoost) to predict `Revenue`.
5. **Evaluation** — use metrics suited to imbalanced classes (accuracy, precision/recall, F1, ROC-AUC) since purchase events are typically a minority class.
6. **Insights** — identify which features (e.g., `PageValues`, `ExitRates`, `TrafficType`) most influence purchase likelihood, and translate into business recommendations.
